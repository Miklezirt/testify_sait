# ROOMS — рабочий MVP гостиничной системы

Next.js 16 + TypeScript + PostgreSQL 17 + Prisma 6 + Auth.js 5 Credentials + Tailwind 4.
Исходный `index.html` сохранён как визуальный референс; приложение запускается через Next.js.

## Что работает

Личная авторизация по email (логину) и паролю; три уровня доступа; управление номерами,
вместимостью, ценой и готовностью; календарь на 14 дней с переходом между датами;
создание/изменение/отмена брони; справочник гостей и история их бронирований;
заезд, выезд, автоматическая задача уборки; предоплата, доплаты, возврат, остаток,
наличные/карта/перевод/другое; защищённые документы; неизменяемый журнал и экспорт CSV.
Интерфейс работает на компьютере и телефоне, данные обновляются каждые 30 секунд.

## Доступ

| Возможность                                               | Владелец (`owner`) | Администратор (`admin`) | Сотрудник (`staff`) |
| --------------------------------------------------------- | ------------------ | ----------------------- | ------------------- |
| Календарь, гости, брони, заезд/выезд, приём оплат, уборка | Да                 | Да                      | Да                  |
| Создание и изменение номеров                              | Да                 | Да                      | Нет                 |
| Загрузка, скачивание и удаление документов                | Да                 | Да                      | Нет                 |
| Возврат оплаты                                            | Да                 | Нет                     | Нет                 |
| Полный журнал действий и CSV                              | Да                 | Нет                     | Нет                 |
| Учётные записи, роли, пароли, отключение доступа          | Да                 | Нет                     | Нет                 |

Каждый входит под своей учётной записью. Владелец создаёт записи в разделе
«Учётные записи», задаёт пароль от 12 символов и уровень доступа. Самого себя
отключить или лишить роли владельца нельзя. Роль и активность проверяются в базе
при каждом запросе. Смена пароля завершает старые сеансы. Время сеанса — 8 часов.
После 10 попыток входа с одним email действует ограничение на 15 минут.

Журнал фиксирует пользователя и его роль на момент события, время, действие, ID записи
и подробности изменений брони/платежа/номера/учётной записи. Записываются входы,
выходы, создание/редактирование, переходы статусов, оплаты, возвраты, завершение уборки
и операции с документами. Пароли, ключи и содержимое документов в журнал не попадают.
События нельзя удалить или изменить через приложение; PostgreSQL также запрещает
UPDATE/DELETE журнала триггером. Владелец видит последние 200 событий и экспортирует
полный журнал без удаления старых записей. Это журнал бизнес-операций, а не запись
каждого движения мыши или просмотренного экрана.

## Локальный запуск

Нужны Node.js **22+**, pnpm **11.25.0**, Docker с Compose. Prisma 6 выбран для зрелого
PostgreSQL-клиента и совместимости миграций. Auth.js 5 используется в зафиксированной
версии beta.30; точные версии всех пакетов закреплены lock-файлом.

```sh
corepack enable
corepack prepare pnpm@11.25.0 --activate
pnpm install --frozen-lockfile
cp .env.example .env
```

Заполните в `.env`:

- `AUTH_SECRET`: случайная строка, например результат `openssl rand -base64 32`.
- `DOCUMENT_KEY`: результат `openssl rand -hex 32` (64 hex символа).
- `SEED_OWNER_PASSWORD`, `SEED_ADMIN_PASSWORD`, `SEED_STAFF_PASSWORD`: **разные** пароли
  длиной минимум 12 символов. Email можно заменить своими.
- `AUTH_URL=http://localhost:3000`, `HOTEL_TIMEZONE=Europe/Moscow`.

```sh
docker compose up -d db
pnpm db:migrate
pnpm db:seed
pnpm dev
```

Откройте http://localhost:3000. Логины по умолчанию: `owner@example.test`,
`admin@example.test`, `staff@example.test`; пароли — те, которые вы указали в `.env`.
Готовых общих паролей в коде нет. Seed создаёт 4 номера (№11, №12, Мансарда, №14),
4 вымышленных гостя, текущие/будущие брони, предоплату и уборку.
Seed можно повторять: он не сбрасывает существующие пароли и не переписывает данные.
Даты демо рассчитываются относительно текущего дня гостиницы. Паспортов в seed нет.

Для проверки production-сборки:

```sh
pnpm build
pnpm start
```

## Правила бронирования и денег

Интервал проживания `[заезд, выезд)`: дата выезда доступна следующей брони.
Пересечения запрещены сервером и PostgreSQL exclusion constraint с `btree_gist`,
включая одновременные запросы и записи напрямую в базу. Вместимость проверяется
на сервере. В прошлом нельзя создать новую бронь. Отменённые брони не занимают номер.
Завершённые проживания остаются в истории занятости.

Внутренние статусы Prisma: `booked`, `checked_in`, `completed`, `cancelled`.
В интерфейсе они отображаются по-русски; `checked_in` соответствует checked-in.
Допустимые переходы: booked → checked_in → completed или booked → cancelled.
Заселение возможно только в даты брони и в готовый номер; нельзя заселить второго
гостя, пока предыдущий не выселен. Для проживания можно продлить/сократить выезд,
изменить стоимость, количество гостей, бельё и комментарий; номер, основной гость
и дата заезда остаются прежними. Для ожидающей брони доступно полное редактирование.

Выезд создаёт уборку и освобождает неиспользованные ночи. При выезде в день заезда
сохраняется минимум одна ночь. До завершения уборки новый заезд блокируется.
Просроченный выезд отображается на главной и требует действий администратора.

Деньги хранятся целыми копейками; предоплата — запись платежа, остаток = стоимость −
сумма платежей с учётом возвратов. Переплаты и возвраты сверх оплаченного запрещены.
Отмена не удаляет платежи и не выполняет автоматический возврат: его отдельно делает
владелец. Выезд возможен с долгом, который сохраняется в разделе оплат. Карта и
перевод — учёт уже принятой оплаты, интеграции с эквайрингом в этом MVP нет.
В брони указан основной гость и число проживающих; документы привязаны к гостю.

## Документы и сохранность

PDF/JPEG/PNG до 5 МБ. Тип проверяется по содержимому, а не только расширению.
Файлы шифруются AES-256-GCM и хранятся в PostgreSQL, без `/public`, публичных URL
или файлов на диске. Скачивание проходит через авторизацию и проверку роли,
отдаётся как attachment с `Cache-Control: private, no-store` и записывается в журнал.
Одинаковый ключ необходим всем экземплярам приложения. Сохраните `DOCUMENT_KEY`
в менеджере секретов и отдельной защищённой резервной копии: без него восстановить
содержимое документов нельзя. Смена ключа требует отдельной процедуры перешифрования.

`.env`, зависимости, дампы и файлы с секретами исключены из Git. Не помещайте реальные
документы гостей в репозиторий, demo-данные или тестовые фикстуры.

## Проверки

```sh
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm test:integration
```

Интеграционные тесты поднимают **отдельный временный PostgreSQL 17**, применяют обе
миграции и запускают production-приложение на порту 3317. Рабочая база из `.env`
не используется. Проверяются конкурирующие брони, ограничение вместимости,
соседние даты, изменение версии, оплаты/возвраты, статусы, уборка, журнал,
Auth.js, разделение ролей, защита от чужого Origin, закрытые файлы и отзыв сеанса.
Нужны свободные порты 55439 (можно задать `TEST_PG_PORT`) и 3317.
Для embedded PostgreSQL разрешены необходимые postinstall-скрипты в pnpm-workspace.yaml.

Проверка браузером (включая узкий экран и создание учётной записи):

```sh
pnpm exec playwright install chromium
TEST_BROWSER=true pnpm test:integration
```

## Деплой на сервер

1. Подготовьте Linux-сервер с Docker/Compose и доменом. Клонируйте репозиторий.
2. Создайте `.env` из примера. Установите уникальные секреты, сильный
   `POSTGRES_PASSWORD`, пароли пользователей, `AUTH_URL=https://your-domain`.
   Поставьте `SEED_DEMO=false`; `DATABASE_URL` для локального запуска миграций должен
   содержать тот же пароль PostgreSQL. В Docker для app адрес базы подставляется автоматически.
3. Запустите PostgreSQL, примените миграции и создайте пользователей:

```sh
docker compose up -d db
docker compose --profile tools build tools
docker compose --profile tools run --rm tools pnpm db:migrate
docker compose --profile tools run --rm tools node --import tsx prisma/seed.ts
docker compose --profile app up -d --build app
```

Сервис `tools` содержит инструменты миграций и seed; приложение запускается из
минимального production-образа под пользователем без прав root. Все параметры
для контейнеров передаются через `.env`; секреты не встраиваются в образ.

4. Настройте Caddy/Nginx перед `127.0.0.1:3000` с HTTPS и передачей Host/
   X-Forwarded-Proto. Host должен соответствовать AUTH_URL. Ограничьте тело запроса
   на прокси до 6 МБ. Порт базы опубликован только на localhost.
5. Настройте ежедневную резервную копию PostgreSQL (`pg_dump`) в закрытое хранилище,
   отдельно сохраните ключ документов и периодически проверяйте восстановление.

Можно запускать `pnpm db:migrate`, `pnpm db:seed`, `pnpm build`, `pnpm start` напрямую
на сервере с Node 22+, подключаясь к управляемому PostgreSQL. База должна поддерживать
расширение btree_gist. Для нескольких экземпляров приложения используйте общий
PostgreSQL, одинаковые AUTH_SECRET/DOCUMENT_KEY и AUTH_URL. Файлы на локальном диске
не требуются. Обновление: резервная копия → миграции → новый образ → перезапуск app.

CI запускает lint, TypeScript, unit, build и интеграционные HTTP-проверки. Браузерная
проверка доступна отдельно указанной командой. Docker-сборку проверяйте в окружении
с Docker; в среде разработки этой задачи Docker отсутствовал.
